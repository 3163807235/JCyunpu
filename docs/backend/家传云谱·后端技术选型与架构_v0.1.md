## 1. 目标与非目标

### 1.1 目标

- 支撑 MVP 垂直切片：注册登录 → 建谱/加人 → 录人与关系 → 流程推进 → 牒记式 PDF → 归档 → 订阅额度拦截 → 运营后台最小集。  
- 与现有 Vue3 前端 Mock 契约平滑替换（统一 `{ code, msg, data }`、分页 `current/size/records/total`）。  
- 落实租户隔离、额度强校验、协作编辑锁、支付幂等、异步重任务。

### 1.2 非目标（开仓首期不做）

- 微服务拆分、分库分表、全量 Elasticsearch。  
- 苏式排版正式引擎、AI OCR 生产级、微信小程序后端专版（属 V1.5+ / Spike）。  
- 「互联网级百万 QPS」容量设计（产品未给出该流量模型；见 §7）。

## 2. 技术选型（已冻结）

| 层级 | 选型 | 说明 |
|------|------|------|
| 语言 / 运行时 | **Java 17+** | LTS；与国内支付/运维生态匹配 |
| 框架 | **Spring Boot 3.x** | Web / Validation / Actuator |
| 安全 | **Spring Security + JWT**（Access + Refresh） | 对齐前端 token / 刷新；后台角色与前台租户用户分离 |
| ORM | **MyBatis-Plus**（已冻结） | 复杂族谱 SQL / 动态条件多；禁止字符串拼 SQL；**不采用** JPA 作为主方案 |
| 主库 | **MySQL 8.0** | InnoDB；utf8mb4；JSON 字段按产品实体使用 |
| 缓存 / 锁 / 限流 | **Redis 7.x** | 编辑锁、短信验证码、接口限流、热点缓存 |
| 消息队列 | **RabbitMQ**（已冻结） | PDF、快照、OCR、回收站清理、异步通知；**不采用** RocketMQ（首期） |
| 对象存储 | **MinIO**（开发）/ **阿里云 OSS**（生产） | Attachment、PDF、快照分片 |
| API 文档 | **springdoc-openapi 3** | 与《OpenAPI 接口目录》同步；CI 可校验漂移 |
| 迁移 | **Flyway** | 唯一 Schema 变更入口 |
| 定时任务 | **Spring Schedule**（MVP）→ 后期可换 XXL-JOB | 订单超时、锁扫尾、回收站期满 |
| 构建 | **Maven**（已冻结） | 单模块起步：`jcyunpu-server`；**不采用** Gradle（首期） |
| 观测 | Actuator + 结构化日志（JSON）+ 可选 Prometheus | 对齐 §5.4 告警思路 |

**明确不引入（首期）**：Kafka、Seata 分布式事务、Service Mesh、自研网关（可用 Nginx / 云负载均衡）、JPA 主栈、RocketMQ、Gradle。

## 3. 逻辑架构

```
                    ┌─────────────┐     ┌──────────────┐
  Web / 运营后台 ──►│ API Gateway │────►│  jcyunpu-api  │  Spring Boot 单体
  (Vue3)            │ Nginx/LB    │     │  (应用层)     │
                    └─────────────┘     └──────┬───────┘
                                               │
               ┌───────────────┬───────────────┼───────────────┐
               ▼               ▼               ▼               ▼
           MySQL 8          Redis           MQ Broker      对象存储
          (业务主库)     (锁/限流/缓存)    (异步任务)     (OSS/MinIO)
                                               │
                                               ▼
                                        Worker 同进程消费
                                        (PDF / 快照 / 清理)
```

**形态**：模块化单体（package by domain），同一进程消费 MQ。任务变重后再拆 Worker 进程，不先拆微服务。

## 4. 关键设计约定

### 4.1 租户隔离

- 付费与额度归属 **Tenant**；请求上下文注入 `tenantId` + `userId`。  
- 协作成员 **不改变** 自身 `tenant_id`（产品 §5.3）；访问他谱靠 Collaborator / GenealogyMember 授权校验。  
- 所有业务查询默认带授权谓词（谱 ID ∈ 用户可访问集合），禁止只靠前端隐藏菜单。

### 4.2 三层身份（强制）

| 层 | 载体 | 后端校验要点 |
|----|------|----------------|
| L1 成员 | `genealogy_member` | 只读；写接口一律 403 |
| L2 协作 | `collaborator` | 角色矩阵 § 权限表；占席位 |
| L3 本期组编 | `project` 名录字段 | 仅名录；加邀 L2 单向，不自动撤权 |

详见成员专题；与 Collaborator 冲突时以专题为准。

### 4.3 统一响应与错误码

对齐根目录《必读文档》：

```json
{ "code": 200, "msg": "success", "data": {} }
```

建议预留业务码段（开仓后写入枚举表）：`2xxxx` 认证、`3xxxx` 权限/成员、`4xxxx` 额度/订阅、`5xxxx` 流程门禁、`6xxxx` 锁冲突。

### 4.4 分页

请求：`current` + `size`；响应：`records` + `total`（可兼容《必读文档》多字段探测，**后端产出固定用这套**）。

## 5. 关键能力落地

### 5.1 协作编辑锁（§1.6）

| 项 | 约定 |
|----|------|
| 存储 | Redis：`lock:{resourceType}:{resourceId}` |
| 值 | `{ userId, userName, genealogyId, expireAt }` |
| TTL | 无心跳 60s 视断线；业务超时 5 分钟无操作释锁 |
| 续租 | 编辑页 30s 心跳接口续 TTL |
| 冲突 | 非持锁人写 → 业务码「锁冲突」+ 当前编辑人 |
| 强制接管 | 仅 owner / 主编；写 OperationLog |

MVP 可不做 WebSocket，前端轮询或写前探测即可（探测 ≤100ms，§5.1）。

### 5.2 额度（§1.5 / 1.7.13）

- 扣减 / 返还与业务写同事务；`quota_transaction` 追加流水，`subscription`（或额度账户表）维护余额 + **version 乐观锁**，冲突重试。  
- 回收站占用不释放；`auto_purge` / `manual_purge` 才返还。  
- 恢复前校验剩余额度。  
- **后端强校验**，前端拦截仅体验优化。

### 5.3 支付与订单

- 下单 → 待支付；30 分钟超时关单（定时或延迟消息）。  
- 微信 / 支付宝回调：**验签 + 订单号幂等**；状态机严格按 §1.7.12。  
- 入账订阅 / 额度与流水同事务；失败可补偿任务，禁止「回调成功但额度未加」无痕迹。

### 5.4 异步任务

| 任务 | 触发 | 结果 |
|------|------|------|
| 牒记式 PDF | 用户导出 / 定稿 | 任务状态查询 + 文件写入 OSS |
| 版本快照 | 归档 | 快照路径写入 VersionSnapshot；大谱分片策略见产品 |
| 回收站期满 | 定时 | 软删确认 + 额度返还流水 |
| OCR（非 MVP 硬指标） | 后期 | 独立队列与限流 10 次/分钟 |

API 只创建任务 ID，禁止同步堵死 HTTP 线程超过数秒（PDF SLA 可达分钟级）。

### 5.5 附件上传

- 推荐：**服务端签发 STS / 预签名 URL → 直传 OSS → 回调或确认接口写 Attachment 元数据并扣存储额度**。  
- 病毒扫描：MVP 可记「待接入」钩子；正式上线对齐 §5.3。

### 5.6 防抖与限流

- 登录 5 次/分钟、注册 3 次/分钟、邀请码预览/加入按 IP 限流（成员专题建议约 10 次/分钟）。  
- 写接口幂等键（可选 `Idempotency-Key`）用于支付与建谱等高风险操作。

1. 冻结本目录 OpenAPI 目录 → 导出/手写 OpenAPI YAML（开仓后）。  
2. 前端 `VITE_*` 指向真实 API；按模块关闭 Mock。

4. 优先打通：`auth` → `genealogy` + `member` → `person/relationship` → `subscription` → `workflow` → `export/archive` → `ops`。

## 7. 容量与「高并发」边界

产品 §5.1 给的是 **时延 SLA**（500 人谱、PDF 分钟级），不是峰值 QPS。

| 场景 | MVP 假设 | 手段 |
|------|----------|------|
| 在线协作 | 单谱同时编辑者个位数～十数 | Redis 锁足够 |
| 额度并发扣减 | 同租户突发写 | DB 事务 + version |
| 导出 / 快照 | 偶发重 CPU | MQ + 限流并发 Worker |
| 公开分享读 | 可增长 | CDN + OSS；热点可缓存 |

**结论**：Java + MySQL + Redis + MQ 可覆盖产品所述规模。若未来要支撑未登录海量读或营销峰值，再增只读副本 / CDN / 缓存，不作为开仓前置。
