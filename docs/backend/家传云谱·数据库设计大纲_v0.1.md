## 1. 总则（已写死）

| 项 | 约定 |
|----|------|
| 引擎 | InnoDB |
| 字符集 | **`utf8mb4` / `utf8mb4_0900_ai_ci`** |
| 主键 | **`bigint` 自增**（MVP）；对外编号与主键分离（如 `genealogy_no`） |
| 时间 | **`datetime(3)`**；业务按 **`Asia/Shanghai`** 解释；库内不存时区后缀 |
| 软删 | `is_deleted` + `deleted_at`；列表默认过滤 |
| JSON | MySQL JSON；用于 `granted_quota`、`metadata`、项目名录等 |
| 迁移 | **仅 Flyway**；禁止手工改生产表结构不留版本 |
| 额度版本 | `subscription.version`（或独立额度账户表）乐观锁字段 **必有** |

## 2. 表清单（MVP）

### 2.1 账号与计费

| 表名 | 产品实体 | 要点 |
|------|----------|------|
| `tenant` | Tenant | 计费与数据隔离顶层 |
| `user` | User | 登录账号；`tenant_id` 主账号归属；手机号加密/脱敏存储策略见 §5.3 |
| `subscription` | Subscription | 一人一租户订阅；人物/存储额度上限；权益开关 |
| `order` | Order | `order_no` 唯一；支付状态机 |
| `quota_transaction` | QuotaTransaction | 只追加不改删；`(tenant_id, quota_type, created_at)` |
| `sms_code` 或 Redis | — | MVP 验证码优先 Redis，表可选 |

**额度并发**：在 `subscription`（或独立 `quota_account`）上保留 `version`；扣减事务内校验 `balance` 并写流水。

### 2.2 族谱与身份

| 表名 | 产品实体 | 要点 |
|------|----------|------|
| `genealogy` | Genealogy | `tenant_id`；`genealogy_no` **租户内唯一**；`owner_user_id` 冗余；`surname` 本族姓氏（V3） |
| `collaborator` | Collaborator | L2；`(genealogy_id, user_id)` 唯一；角色/席位 |
| `genealogy_member` | GenealogyMember | L1；`(genealogy_id, user_id)` 唯一；不占协作席位 |
| `genealogy_invite_code` | GenealogyInviteCode | 有效码按谱唯一（`status=1` 部分唯一索引或应用保证） |

### 2.3 活数据（挂族谱，不挂项目）

| 表名 | 产品实体 | 要点 |
|------|----------|------|
| `person` | Person | `genealogy_id` 主关联；`(genealogy_id, person_no)` 唯一 |
| `relationship` | Relationship | 邻接表；索引 from/to + genealogy |

### 2.4 修谱项目与产物

| 表名 | 产品实体 | 要点 |
|------|----------|------|
| `project` | Project | `current_stage` 1–5（五步）；`layout_dirty`；editors 等 JSON/子表 |
| `chapter` | Chapter | 可空 `project_id`（族谱级章节） |
| `family_event` | FamilyEvent | 族谱级 |
| `family_rule` | FamilyRule | 族谱级 |
| `renewal_item` | RenewalItem | 续修增补；V1.5 可建表，MVP 可延后 |
| `version_snapshot` | VersionSnapshot | 快照路径指 OSS；大谱分片索引文件 |

### 2.5 附件、分享、锁、审计

| 表名 | 产品实体 | 要点 |
|------|----------|------|
| `attachment` | Attachment | `storage_path`；占存储额度 |
| `share_link` | （分享） | token 唯一；过期；只读 |
| `edit_lock` | （可选表） | **推荐 Redis**；若落库则需 TTL 扫尾任务 |
| `operation_log` | OperationLog | 分区或按月归档策略后期再定；不可业务删除 |
| `async_task` | — | PDF/导入等任务状态 |

### 2.6 运营（可复用或扩展）

运营后台以查询上述表为主；如需平台角色表：

| 表名 | 说明 |
|------|------|
| `admin_user` / 复用 `user.roles` | 与前台租户用户权限模型分开文档说明 |
| 系统菜单 | 若 `VITE_ACCESS_MODE=backend`，需菜单表或配置接口 |

## 3. ER 关系（逻辑）

```
tenant 1──1 user(主账号)
   │
   ├──1──1 subscription
   ├──1──N order
   ├──1──N quota_transaction
   └──1──N genealogy
              ├──1──N person
              ├──1──N relationship
              ├──1──N collaborator          (L2)
              ├──1──N genealogy_member      (L1)
              ├──1──N genealogy_invite_code
              ├──1──N attachment
              ├──1──N family_event / family_rule
              ├──1──N project
              │         ├──1──N chapter (项目级)
              │         ├──1──N version_snapshot
              │         └──1──N renewal_item
              └──1──N operation_log
```

**硬规则**：Person / Relationship **不得**以 `project_id` 作为归属主键（`project_id` 仅可追溯）。

## 4. 必须落地的唯一 / 检查约束

| 对象 | 约束 |
|------|------|
| `genealogy` | `(tenant_id, genealogy_no)` UNIQUE |
| `person` | `(genealogy_id, person_no)` UNIQUE WHERE 未删除（或软删下应用保证） |
| `collaborator` | `(genealogy_id, user_id)` UNIQUE |
| `genealogy_member` | `(genealogy_id, user_id)` UNIQUE |
| `order` | `order_no` UNIQUE |
| `share_link` | `token` UNIQUE |
| `invite_code` | `code` 全局或足够熵 + 查询；有效态每谱一条 |

支付状态、流程阶段等 **枚举合法性以服务端状态机为准**，DB 可用 TINYINT + 注释。

## 5. 索引（首批）

直接采用产品文档索引建议，开仓时写入迁移脚本，至少包括：

- `person(genealogy_id, generation)`、`(genealogy_id, person_no)`、`(genealogy_id, is_changed_since_archive)`  
- `relationship(genealogy_id, from_person_id)`、`(genealogy_id, to_person_id)`  
- `order(tenant_id, payment_status, created_at)`、`(order_no)`  
- `quota_transaction(tenant_id, quota_type, created_at)`  
- `attachment(genealogy_id, attachment_type)`  
- `genealogy(tenant_id, status)`、`(owner_user_id)`  

搜索达 V2 万人级再评估全文索引 / ES，不在本大纲强制。

## 6. 多租户与授权查询

1. **拥有者谱**：`genealogy.tenant_id = ctx.tenantId` 且 owner 匹配。  
2. **协作谱**：`collaborator.user_id = ctx.userId`。  
3. **成员谱**：`genealogy_member.user_id = ctx.userId`。  
4. 列表「我的族谱」= 三者 UNION；写操作仅 Owner/Collab 且角色允许。  

禁止「只校验登录、不校验谱授权」。

---

## 7. 与对象存储的边界

- DB **只存路径与元数据**，不存二进制。  
- `version_snapshot.data_snapshot_path` 指向索引或单文件；万人分片策略按产品 §1.7.6 说明。  
- 删除附件：先软删元数据，期满或彻底删除后再删 OSS（避免孤儿或误删）。
