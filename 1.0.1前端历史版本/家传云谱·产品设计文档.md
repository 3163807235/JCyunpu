## 第零部分：产品概述与版本规划

### 0.1 产品定位与价值主张

家传云谱是一款面向家族修谱场景的 SaaS 平台，以"低门槛数字化修谱 + 传统版式专业输出 + 世代永续续修"为核心价值，帮助家族将纸质老谱转化为可迭代的数字资产，实现家谱数据采集、内容编排、质量审核、排版定稿、发布归档的全流程线上化。

**核心价值主张**：
- **降低修谱门槛**：无需专业排版技能，结构化录入即可生成符合传统规范的谱书
- **保障修谱质量**：六步流程 + 多人协作 + 质量审核机制，兼顾效率与严谨
- **实现永续传承**：版本封存 + 多期续修 + 增量编辑，让族谱代代延续

### 0.2 目标用户画像

| 用户角色 | 典型特征 | 核心诉求 |
|----------|----------|----------|
| **族谱主编/发起人** | 家族中热心修谱的长辈或中年人，有一定文化水平，熟悉家族历史 | 高效组织协作、把控修谱质量、输出专业谱书 |
| **房头采编** | 各房支负责收集本房资料的人员，年龄跨度大，计算机水平参差 | 简单易用的数据录入工具、清晰的任务分工 |
| **校勘员** | 负责校对审核的家族文化人，对族谱内容准确性要求高 | 批量校对、疑点标注、版本对比 |
| **普通族人/浏览者** | 家族成员，对族谱有查阅需求，不参与编辑 | 方便查看世系、查找宗亲、了解家族历史 |
| **平台运营管理员** | 平台方运营、客服、运维人员 | 用户管理、内容风控、数据监控、售后处理 |

### 0.3 MVP 范围定义（V1.0 一期）

**一期目标**：验证核心流程跑通，支持单族谱从创建到归档的完整闭环，满足中小家族（500人以内）的首修需求。

**设计原则**：MVP 按"垂直切片"裁剪——先跑通一条最短可用路径（建谱→录人/关系→一种导出→拥有者+采编），再逐步扩入校勘双审、多版式、家族文化全量、续修与分享。MVP 不按全文规格交付，苏式排版独立 Spike 验证可行性后再决定是否纳入一期。

#### 0.3.1 MVP 核心切片（一期必做，按交付优先级排序）

| 优先级 | 功能 | 说明 |
|--------|------|------|
| P0 | 用户注册登录与账号管理 | 手机号验证码登录 |
| P0 | 单族谱创建与基础设置 | 族谱名、堂号、始祖、隐私设置 |
| P0 | 人物数据采集（增删改查） | 手动新增为主，批量导入Excel为辅 |
| P0 | 亲属关系管理 | 父子、配偶、出继/嗣子核心关系 |
| P0 | 谱书章节管理 | 凡例、谱序、传记富文本编辑 |
| P0 | 牒记式排版 + PDF导出 | **先上牒记式**（实现成本低），苏式垂丝独立 Spike |
| P0 | 版本快照与归档 | 归档后只读封存 |
| P0 | 订阅体系 | 试用+基础年付，额度管控 |
| P1 | 协作成员管理 | **MVP仅拥有者+采编两角色**，主编/校勘/只读降为V1.5 |
| P1 | 世系图可视化 | 垂丝图缩放拖拽 |
| P1 | 字辈派语设置与校验 | 可存+存疑策略 |
| P1 | 附件档案管理 | 图片上传与管理 |
| P2 | 后台管理（最小集） | 用户列表+订单列表+审计日志，内容审核/敏感词降为V1.5 |
| P2 | 家族文化（最小集） | **MVP仅上家规家训+家族大事记两个Tab**，姓氏源流/堂号/相册降为V1.5 |
| P2 | 族内只读分享链接 | 拥有者生成分享链接，族人可只读浏览（无编辑），MVP末段上线 |

#### 0.3.2 MVP 简易模式（降门槛）

针对个人用户和小家族场景，提供"简易模式"选项：

| 维度 | 标准模式 | 简易模式 |
|------|---------|---------|
| 适用用户 | 专业修谱团队、大家族 | 个人、小家族（50人以内） |
| 流程 | 六步强制流程（MVP标准模式由拥有者代行校勘+终审，V1.5开放全角色双审） | 跳过"质量审核"阶段（六步减一为五步，又称"快捷成谱"），项目启动→数据采集→内容编排→排版定稿→发布归档 |
| 角色 | 拥有者+主编+采编+校勘+只读（V1.5全角色；MVP仅拥有者+采编） | 仅拥有者（单人操作） |
| 版式 | 牒记式（MVP）+ 苏式（Spike/V1.5） | 牒记式（预置模板，不需配置排版参数） |
| 导入 | 批量导入Excel | 手动新增为主 |
| 可切换 | — | 可升级至标准模式 |

**切换规则**：用户创建族谱时选择模式，后续可在设置中从简易模式升级为标准模式。**不可降级**——因为标准模式下会产生审核状态、角色授权、校勘批注等流程语义数据，降级后这些数据失去含义、无法还原。升级时自动补齐质量审核阶段入口，已有数据全部保留。

#### 0.3.3 MVP 暂不做（Out of Scope，V1.5+ 迭代）

- 多族谱管理（一期仅支持单族谱，通过 Subscription.max_genealogy_count=1 硬限制，试用套餐限1个；基础/专业套餐可在后台配置上限，但MVP默认仍为1个）
- 多期续修功能（一期仅支持初始修谱，续修在 V1.5 上线）
  - **MVP 边界说明**：续修功能在 MVP 中仅做数据模型预留（Project 实体保留 `project_type=2` 续修类型、`base_version_id` 基准版本字段、VersionSnapshot 快照机制），前端续修相关入口（发布归档页"续修发起"Tab、版本对比功能、续修继承选项）在 MVP 中隐藏展示并标注"V1.5 上线"，不做功能开发
- **苏式垂丝排版**（独立 Spike 验证可行性后决定是否纳入一期，MVP默认仅上牒记式，Spike通过后视情况提前）
- 宝塔式、欧式分栏版式（V1.5 上线）
- **主编、校勘、只读角色**（MVP仅拥有者+采编，V1.5开放全角色）
- **质量审核双审流程**（MVP简易模式跳过审核阶段，标准模式由拥有者代行校勘+终审，V1.5强制双审）
- **家族文化全量**（姓氏源流、堂号起源、家族相册三个Tab降为V1.5，MVP仅上家规家训+大事记）
- 高级协作功能（任务分配、评论@、实时协作）
- 移动端 App（一期优先 Web 端响应式）
- 族谱分享与传播机制（完整分享/族人注册浏览放 V2.0；**MVP末段上族内只读链接**，作为增长试验）
- 运营工具（优惠券、拼团、分销）

### 0.5 成功指标

**核心指标**：

- 单族谱平均人物数 ≥ 80 人
- 修谱完成率（从项目启动到发布归档）≥ 20%
- 付费转化率（试用 → 付费）≥ 15%
- 续费率 ≥ 40%

### 0.6 术语表

平台业务流程采用"传统修谱术语 + 现代软件术语"双名映射，文档中以现代术语为主、传统术语为辅，便于开发团队理解业务语义。

#### 0.6.1 流程术语：现代 ↔ 传统 映射

| 现代术语（文档主用） | 传统术语（业务上下文） | 含义 |
|---------------------|----------------------|------|
| 项目启动 | 发起 | 新建修谱/续修项目，初始化项目信息、凡例、负责人 |
| 数据采集 | 采录 | 房头采编录入人物、史料、附件、亲属关系 |
| 内容编排 | 编修 | 主编整合数据、规整世系、完善谱文、初审内容 |
| 质量审核 | 校订 | 校勘员专项勘误、批注、疑点复核、驳回整改 |
| 排版定稿 | 付梓 | 智能排版+手动微调、版式锁定、生成定稿谱稿 |
| 发布归档 | 发谱归档 | 版本封存、对内对外公示、续修台账记录、流程闭环 |

#### 0.6.2 进度条命名：标准模式 vs 简易模式

> **关键区分**：产品中有两种不同含义的"五步"，**绝对不能混用同一套进度条语义**。

| 命名 | 适用模式 | 展示形式 | 对应内部阶段 | 设计目的 |
|------|---------|---------|-------------|---------|
| **五步成谱** | 标准模式 | 5段进度条（壹→伍） | 启动→采集→编排→审核+定稿→归档（内部6态合并为5段展示，"三校定稿"=质量审核+排版定稿合并） | 仪式感营销，符合传统修谱心智 |
| **快捷成谱** | 简易模式 | 5段进度条（无编号仪式感） | 启动→采集→编排→定稿→归档（跳过质量审核，内部5态即5段） | 轻量快速，明确告知"已跳过会审" |

**实现规则**：
- 标准模式下，族谱总览页顶部展示**"五步成谱"**仪式感进度条，第四段标注"三校定稿"，内部状态机仍按 6 步执行
- 简易模式下，展示**"快捷成谱"**进度条，共 5 段（启动→采集→编排→定稿→归档），进度条旁用浅灰色小字标注"已跳过会审，可随时升级为标准模式"
- 简易模式升级为标准模式后，进度条自动切换为"五步成谱"样式，补充质量审核阶段入口

#### 0.6.3 核心业务概念

| 术语 | 说明 |
|------|------|
| 族谱 / Genealogy | 一个家族的完整谱系数据，包含人物、关系、章节、附件等 |
| 修谱项目 | 一次具体的修谱工作（初始修谱或某一期续修），有独立的六步流程 |
| 世系 | 家族世代相承的系统，以父子关系为主线 |
| 字辈 | 家族规定的世代命名用字，用于区分辈分 |
| 房头 | 家族的分支，通常以某一代祖先的几个儿子分别立房 |
| 续修 | 在已有谱书基础上进行增补、勘误，形成新版本 |
| 垂丝图 | 以竖线（丝）连接父子的世系图样式 |
| 牒记式 | 以人物传记条目为主体、按世系排列的谱书格式 |
| 苏式 | 苏洵创立的谱式，以世代为经、以父子为纬，垂丝连线的世系图格式 |

### 0.7 信息架构说明

为降低用户学习成本、简化侧边栏层级，前后台均采用"主菜单 + 页面内 Tab"的二级信息架构：主菜单聚焦核心任务场景，同一主题下的细分功能通过页面顶部 Tab 切换，而非散落在侧边栏中。

前台单族谱的核心菜单围绕修谱流程设计，用户进入族谱后首先看到的是**族谱总览**，顶部进度条清晰展示当前处于哪个阶段（标准模式展示"五步成谱"，简易模式展示"快捷成谱"），每个阶段内的功能通过 Tab 或分区组织。

| **专属客服** | ✗ | 工单 | 工单 + 1对1 |

**额度用尽拦截规则**：人物额度或存储额度用尽时，**禁止新增**（新增人物、上传附件、新建项目），但**允许编辑已有数据**（修改人物信息、调整关系、编辑谱文）。购买扩容包后立即恢复新增。**回收站中的数据继续占用额度**，需彻底删除或等待30天期满自动释放后额度才会恢复。

**订阅过期拦截规则**：订阅过期/冻结/欠费时，进入**全只读模式**——禁止所有写入操作（新增、编辑、导入、上传），仅保留浏览权限。续费后立即恢复全部操作。

### 0.9 关键用户旅程

#### 旅程一：主编首修全流程（目标态，V1.5 全角色）

```
注册账号（手机号验证码）
  → 创建族谱（填写族谱名/堂号/始祖/隐私设置）
  → 自动生成空族谱+默认初始修谱项目（阶段1：项目启动）
  → 编辑凡例、配置字辈
  → 邀请协作成员（房头采编 + 校勘员）
  → 推进至数据采集（阶段2）
  → 采编录入人物（手动新增/批量导入Excel）
  → 录入亲属关系、上传老谱扫描件/人物照片
  → 录入家族文化内容（姓氏源流/堂号/家规家训/大事记/相册）
  → 主编推进至内容编排（阶段3）
  → 规整世系图、撰写谱文、配置版式
  → 推进至质量审核（阶段4）
  → 校勘员校对批注 → 采编整改 → 校勘标记通过
  → 主编终审放行
  → 推进至排版定稿（阶段5）
  → 选择版式（苏式/牒记式）→ 预览 → 调整参数 → 锁定版式
  → 生成印刷版PDF
  → 推进至发布归档（阶段6）
  → 填写归档摘要 → 执行归档
  → 版本封存，永久只读
```

#### 旅程一 MVP 版：拥有者首修最短路径（P0 切片，MVP 优先交付）

```
注册账号（手机号验证码）
  → 创建族谱（选择简易/标准模式，填写族谱名/堂号/始祖）
  → 自动生成空族谱+默认初始修谱项目（阶段1：项目启动）
  → 编辑凡例、配置字辈
  → 邀请采编协作（可选，MVP仅拥有者+采编两角色）
  → 推进至数据采集（阶段2）
  → 录入人物（手动新增为主，批量导入为辅）
  → 录入亲属关系（父子/配偶）、上传人物照片
  → 录入家规家训+家族大事记（MVP家族文化仅两Tab）
  → 推进至内容编排（阶段3）
  → 撰写谱序/传记、配置牒记式参数
  → 【简易模式跳过质量审核】/【标准模式：拥有者代行校勘+终审】
  → 推进至排版定稿（阶段5）
  → 牒记式预览 → 生成印刷版PDF
  → 推进至发布归档（阶段6）
  → 填写归档摘要 → 执行归档 → 版本封存
```

#### 旅程二：采编录入流程

```
收到邀请短信/链接
  → 注册/登录账号
  → 进入族谱工作台
  → 打开数据采集页 → 人物列表Tab
  → 手动新增人物（录入讳/字/号/世代/生卒/籍贯等）
```

## 第一部分：全局统一规范（前后台通用）

### 1.1 全局布局标准

全站统一采用**左侧可折叠侧边栏 + 顶部固定导航栏 + 中间主内容区**三段式布局，前台、后台布局结构一致，仅菜单内容、配色、功能不同，降低开发、学习、维护成本。

* 侧边栏：默认展开，支持一键折叠，浏览器本地记忆状态，折叠仅显图标、悬浮展示文字
* 顶部栏：固定置顶，包含logo、侧边栏切换、全局面包屑、功能按钮、消息通知、个人中心、当前族谱常驻标识
* 主内容区：独立滚动，顶部底部不跟随滚动，自适应屏幕尺寸

### 1.2 导航通用规则

* 全站强制开启**面包屑导航**，清晰展示当前页面层级，支持点击返回上级页面
* 当前菜单自动高亮，二级菜单自动展开，未选中菜单收起
* 无权限菜单、未开通功能、过期/受限功能菜单自动隐藏，不置灰、不展示，做到界面与权限强一致
* **流程阶段菜单可见性规则**：侧边栏仅显示当前已到达及之前的阶段菜单（如当前处于"内容编排"阶段，则显示"项目启动""数据采集""内容编排"三个菜单，后续阶段菜单不显示）。流程引导由**族谱总览页顶部进度条**承担——标准模式展示"五步成谱"（5段，第四段"三校定稿"=质量审核+排版定稿合并），简易模式展示"快捷成谱"（5段，跳过质量审核），未到达阶段显示为灰色不可点击。用户点击进度条上的已到达阶段可直接跳转。（详见 §0.6.2 进度条命名规则）
* **页面内 Tab 导航**：同一主菜单下的多个功能模块通过页面顶部 Tab 栏切换，Tab 状态反映当前所处子功能，支持通过 URL 直接定位到指定 Tab

### 1.3 计费与数据通用兜底规则（全站核心）

**核心分层规则**

* **平台侧数据永久留存**：因平台运营原因（过期、欠费、冻结、降级、账号封禁）均不会主动删除用户族谱、人物、附件、版本、日志数据，仅做功能权限拦截。用户数据的删除权完全归属于用户本人。
* **用户侧删除规则**：用户主动触发的删除操作，遵循"回收站 + 软删除"二级机制（详见下方 1.3.1）。
* **基础读写拦截（分场景）**：
  - **额度用尽**：禁止新增操作（新增人物、上传附件、新建项目、新建续修），但**允许编辑已有数据**（修改人物、调整关系、编辑谱文、编辑家族文化内容）
  - **订阅过期/冻结/欠费**：进入全只读模式，禁止所有写入操作（新增、编辑、导入、上传），仅保留浏览
* **高阶功能拦截**：过期/额度用尽状态下，禁止排版定稿、禁止版式锁定、禁止PDF印刷成册导出、禁止全谱导出，仅保留单条预览、普通浏览权限
* **双重校验机制**：所有写入操作前端预校验 + 后端强校验，防篡改、防绕过
* **协作计费规则**：所有协作成员的采编、上传、修改、项目操作，均消耗**族谱创建者（租户主账号）**额度，子成员独立无额度

#### 1.3.1 用户侧数据删除机制（回收站 + 软删除）

为兼顾"用户数据自主权"与"数据安全兜底"，所有用户主动删除操作采用二级机制：

**第一级：回收站（30天可恢复）**
* 用户删除族谱、人物、附件等数据时，数据不立即物理删除，而是移入"回收站"
* 回收站保留期为 30 天，期间用户可随时恢复被删除的数据
* **额度占用规则**：回收站中的数据继续占用额度（人物占用人物额度、附件占用存储额度），**不立即释放**。仅在以下两种情形释放额度：
  - **回收站期满自动软删除**：30天期满后数据自动转为软删除，此时额度才释放（QuotaTransaction 记录 change_type=auto_purge）
  - **用户手动彻底删除**：用户在回收站中主动"彻底删除"某条数据，额度立即释放（QuotaTransaction 记录 change_type=manual_purge）
* **恢复时额度校验**：用户从回收站恢复数据时，系统校验当前剩余额度是否足够容纳恢复的数据。额度不足时拦截恢复操作，提示"额度不足，无法恢复，请先扩容或彻底删除其他回收站数据"
* 回收站中数据对正常业务不可见，仅在回收站页面可查看和恢复

**第二级：自动软删除（保留追溯）**
* 回收站期满 30 天后，数据自动标记为"已软删除"状态（`is_deleted = true`）
* 软删除数据在前台完全不可见，普通查询接口不返回
* 后台管理员可通过特殊权限查看软删除数据，用于合规审计、售后申诉等场景
* 软删除数据永久保留，不做物理删除（除非用户主动申请数据擦除并完成合规验证）

**特殊说明：族谱级联删除**
* 用户删除族谱时，该族谱下所有人物、关系、章节、附件、修谱项目、版本快照一并进入回收站
* 族谱删除后，协作成员自动失去访问权限
* 恢复族谱时，其下所有关联数据一并恢复

### 1.4 修谱核心通用规则（含六步流程+续修迭代）

平台严格遵循传统正统修谱范式，固定**项目启动→数据采集→内容编排→质量审核→排版定稿→发布归档**六步闭环递进流程，**禁止越级推进、支持合规回退**，同时支持族谱终身存续、N期永续续修迭代。

> 以下"传统术语 → 现代术语"的映射贯穿全文，后续章节统一使用现代术语。

* 族谱主体唯一：单个族谱永久存续，不重复创建，所有初始修谱、续修项目均挂靠同一族谱，一脉相承
* 版本强隔离：历史定稿版本永久封存只读、不可篡改、不可覆盖；新版续修数据独立编辑、独立流程、独立存档
* 续修继承规则：新建续修默认继承上一版发布归档版本的人物、世系、章节、版式、批注，仅做增量增补、勘误修正，不篡改历史正统史料

**六步流程回退规则**

* 发布归档状态：不可回退，永久封存，仅可新建下一期续修
* 排版定稿状态：仅可回退至【质量审核】，回退自动解锁版式、重置定稿状态、清空固化页码目录
* 质量审核状态：可驳回回退至【内容编排】，自动生成驳回台账与批量批注，标记待整改内容
* 内容编排状态：可回退至【数据采集】，保留已采编数据不清空，仅解锁编辑权限
* 项目启动、数据采集：自由编辑、自由退回，无流程锁限制
* 回退权限限制：仅拥有者、主编可操作流程回退，校勘、采编无回退权限

**质量审核终审放行标准**

* 系统自动判定：项目内所有人物、章节、谱文、附件无「待校对、待整改、存疑未处理」状态
* 支持行业合规容错：主编可手动标记**存疑归档**（单项目内存疑人物数 ≤ 总人物数的 5%，且每条必须填写存疑原因与考证备注）
* 终审双保险：系统校验通过 + 主编手动终审确认，方可进入排版定稿环节，禁止校勘员单人放行
* 存疑标记在后续续修中默认继承，鼓励在续修阶段核实修正

### 1.5 全局通用交互兜底规则

* **空状态兜底**：所有列表无数据时展示标准空状态文案+图标，隐藏筛选、批量操作按钮，无空白页面
* **加载状态兜底**：所有接口请求、页面刷新、文件加载展示统一loading状态，防止重复点击、重复提交
* **报错兜底**：接口失败、网络异常、权限失效统一友好报错提示，记录前端错误日志，不白屏、不崩溃
* **二次确认兜底**：删除、流程推进、流程回退、版式锁定、族谱删除等高风险操作统一二次弹窗确认
* **文件资源兜底**：图片、附件加载失败展示默认占位图，超大文件分片上传、断点续传、超时重试
* **防重复提交**：所有表单提交、数据写入操作1秒防抖锁定，防止重复创建、重复录入数据

### 1.6 全局多人协作锁机制

* 同一人物、同一章节、同一谱文、同一家族大事记、同一家规家训条目**单人独占编辑锁**，A用户编辑中，B用户仅可查看、不可编辑，防止数据覆盖
* 编辑超时自动释锁：无操作5分钟自动释放编辑权限，避免页面卡死占用锁
* 锁状态实时提示：页面展示「当前正在编辑人员」弹窗提示，协作透明无冲突
* 心跳检测：编辑页面每 30 秒向服务端发送心跳续租，网络断开超过 60 秒自动释锁
* 强制接管：族谱拥有者或主编可强制释放他人编辑锁，操作记入审计日志

### 1.7 核心数据模型

本节定义平台核心实体的数据结构与关系，为后端数据库设计提供依据。

#### 1.7.1 实体关系总览

核心实体及其关系如下：

```
租户（Tenant）──1:1── 用户（User，主账号）
    │
    ├──1:1── 订阅（Subscription）
    ├──1:N── 订单（Order）
    ├──1:N── 额度流水（QuotaTransaction）
    └──1:N── 族谱（Genealogy）──1:N── 修谱项目（Project）
                                  │
                                  ├──1:N── 人物（Person）
                                  ├──1:N── 亲属关系（Relationship）
                                  ├──1:N── 谱书章节（Chapter）
                                  ├──1:N── 附件（Attachment）
                                  ├──1:N── 版本快照（VersionSnapshot）
                                  ├──1:N── 协作成员（Collaborator）
                                  ├──1:N── 家族大事记（FamilyEvent）
                                  └──1:N── 家规家训（FamilyRule）

操作日志（OperationLog）──N:1── 族谱（Genealogy）
订单（Order）──N:1── 订阅（Subscription）
```

**关系说明**：
* 一个租户（即一个付费账号）可拥有多个族谱
* 一个族谱下可有多个修谱项目（初始修谱 + 多期续修）
* 人物、关系、章节、附件等数据归属到具体修谱项目，实现版本隔离
* 家族大事记、家规家训归属到族谱级别（非项目级别），因为它们是跨版本累积的文化内容
* 版本快照是修谱项目发布归档时的全量数据副本，永久封存只读

#### 1.7.18 实体关系补充说明

**版本快照范围定义**：版本快照在发布归档时一次性全量快照，包含以下数据：
* **项目级数据**：当前项目的全部人物、亲属关系、谱书章节（含姓氏源流、堂号起源）、凡例
* **族谱级数据**：家族大事记、家规家训（全量，非增量）
* **排版参数**：版式类型、版式配置、页码目录、总页数
* **附件清单**：当前项目关联的全部附件ID和元信息（不含文件二进制，仅记录引用关系）

续修继承时，新项目从基准版本快照中恢复上述数据作为初始状态，增量编辑。

### 1.8 隐私与脱敏统一规则

本节统一定义隐私和脱敏规则，其他章节引用此节，避免规则分散。

#### 1.8.1 族谱隐私模式（Genealogy.privacy_mode）

| privacy_mode 值 | 模式名称 | 含义 |
|-----------------|----------|------|
| 1 | 完全私有 | 仅拥有者、协作成员可访问（需登录+Collaborator关联） |
| 2 | 族内可见 | 拥有者生成"族内浏览链接"，持有链接的族人可只读浏览（不可编辑） |
| 3 | 全网公开 | 任何人无需登录即可浏览公开内容（在世人物仍脱敏） |

#### 1.8.2 在世人物脱敏规则（Genealogy.living_desensitize）

| living_desensitize 值 | 级别名称 | 脱敏字段 | 适用场景 |
|----------------------|----------|----------|----------|
| 1 | 严格脱敏 | 隐藏生卒月日，仅显示名讳+享年范围（如"享年七十有余"） | 默认值，保护在世人物隐私 |
| 2 | 中度脱敏 | 隐藏生卒完整日期，仅显示生卒年份 | 拥有者可手动调低 |
| 3 | 完整显示 | 显示完整生卒日期 | 仅拥有者自己查看时生效，其他角色仍按脱敏规则 |

**脱敏触发条件**：当 Person.is_alive = 1（在世）时，所有展示场景（世系图、人物详情、PDF导出、批量列表）均按 living_desensitize 级别脱敏。已故人物（is_alive=0）不受脱敏限制。

**脱敏角色判定**：
* 拥有者（owner）查看时，living_desensitize 不生效（自己可看完整数据）
* 协作成员查看时，按 living_desensitize 级别脱敏
* 公开浏览者查看时，始终按最严格级别（1）脱敏，无论族谱设置

#### 1.8.3 人物隐私级别（Person.privacy_level）

| privacy_level 值 | 级别名称 | 可见范围 |
|-----------------|----------|----------|
| 1 | 公开 | 所有可访问该族谱的用户均可见（含公开浏览者） |
| 2 | 族内可见 | 仅拥有者和协作成员可见 |
| 3 | 私密 | 仅拥有者可见，协作成员不可见 |

#### 1.8.4 家族相册可见范围

家族相册中每张照片通过 Attachment.metadata 中的 `privacy_level` 字段控制：
* `privacy_level = 1`（公开）：所有可访问族谱的用户可见
* `privacy_level = 2`（族内）：仅拥有者和协作成员可见
* `privacy_level = 3`（私密）：仅拥有者可见

#### 1.8.5 隐私规则优先级

当多级隐私规则同时生效时，按**最严格规则优先**：
1. 人物 privacy_level = 3（私密）→ 仅拥有者可见，忽略其他规则
2. 人物 is_alive = 1（在世）→ 按脱敏规则处理
3. 族谱 privacy_mode = 1（完全私有）→ 仅协作成员可见
4. 以上均不触发时，按各内容默认可见性展示

### 2.1 后台菜单树形结构

后台采用 7 个一级菜单，子功能通过页面内 Tab 切换，减少侧边栏层级、提升操作聚焦度。

## 第三部分：前台用户端设计规范

### 3.1 前台整体定位

面向所有注册用户，支持「创建族谱、数据采集、多人协作、世系展示、版本管理、附件归档、订阅续费、额度管控、排版定稿与发布归档」，适配年费订阅、额度管控、六步修谱流程的完整业务体系，权限、流程、商业化规则形成业务闭环。

### 3.3 前台侧边栏菜单结构

4. **个人中心** —— （点击展开二级：账号信息 / 修改密码 / 消息通知）

**单族谱菜单（进入族谱后）——按流程阶段分组**：

### 3.4 前台逐页面功能

#### 前台页面 01：工作台

**布局**：顶部状态卡片 + 中部门谱快捷入口 + 底部动态记录

**核心展示内容**：

**交互限制**：额度不足、订阅过期时，首页展示醒目续费/扩容引导横幅，隐藏所有新建、续修、定稿、高阶导出功能入口，仅保留阅览权限。

#### 前台页面 02：我的族谱

**布局**：顶部筛选+【创建族谱】弹窗按钮 + 卡片式族谱列表 + 分页 + 回收站入口

**功能说明**：移除独立创建族谱页面，统一为全局模态弹窗，一次性完成基础信息、堂号、始祖、隐私权限配置。

**核心功能**：

* 展示当前账号所有自建族谱：名称、堂号、始祖、创建时间、公开状态、人物总数、修谱/续修项目数
* 搜索/筛选族谱、编辑族谱基础信息、切换公开/私有状态
* 删除族谱（二次强确认，移入回收站，30天内可恢复）
* 回收站入口：查看已删除族谱、恢复族谱、彻底删除（需二次验证）
* 弹窗新建族谱：订阅/额度校验通过方可创建，创建成功自动生成空族谱+默认初始修谱项目
* 点击族谱卡片进入族谱总览页

**回收站规则**：
* 删除族谱后数据保留 30 天，期间可全额恢复
* 30天后自动软删除，前台不可见，后台保留合规追溯
* 删除族谱后人物额度、存储额度立即返还
* 彻底删除操作需手机验证码二次确认，且删除后不可恢复

**拦截规则**：订阅过期、人物额度用尽，隐藏新建族谱按钮，仅可查看、管理已有族谱。

#### 前台页面 03：族谱总览

**布局**：族谱信息卡片 + 六步流程进度条 + 数据统计 + 各阶段快捷入口

**展示**：族谱基础信息、总人物数、章节数、附件数、家族大事记数、家族相册照片数、协作成员数、当前修谱项目状态与所处阶段、历史续修批次记录、各批次定稿时间

**进度条**：页面顶部横贯一个进度条，根据模式不同展示不同样式：
- **标准模式**：展示"五步成谱"仪式感进度条（壹·立堂定源 → 贰·广录族人 → 叁·协同编纂 → 肆·三校定稿 → 伍·颁谱典藏），共 5 段。第四段"三校定稿"内部包含质量审核和排版定稿两个子状态（用户感知为一步，内部状态机按 6 步执行）
- **简易模式**：展示"快捷成谱"进度条（启动 → 采集 → 编排 → 定稿 → 归档），共 5 段。进度条旁标注浅灰色小字"已跳过会审，可升级为标准模式"
- 已完成阶段打勾，当前阶段高亮，未到达阶段灰色不可点击。点击任一已到达阶段可直接跳转对应菜单页面

> 映射关系详见 §0.6.2 进度条命名规则。

**快捷入口**：新增人物、打开世系图、新建版本、管理成员、新建续修项目

**页面定位**：进入族谱后的首屏，承担"概览 + 流程导航"双重角色，用户从此处直观感知项目进度并分流到各阶段页面。

**Tab 1：项目信息**

**Tab 3：团队配置**

#### 前台页面 05：数据采集（阶段 2）

**页面定位**：人物数据录入的核心工作台，所有与人物相关的数据操作都在此页面完成。

**页面结构**：顶部 Tab 栏切换四个子模块

**Tab 1：人物列表**
* 布局：顶部筛选+新增/批量导入按钮 + 人物列表表格 + 分页 + 回收站入口
* 筛选条件：姓名、字辈、世代、性别、在世状态、录入时间、所属修谱/续修项目
* 可操作功能：新增人物（完整支持讳、字、号、行第、字辈、生卒、籍贯、墓葬、传记）；编辑人物、查看详情、删除人物（删除后移入回收站，额度在回收站期满或彻底删除后释放）；批量导入/导出（权限受控、状态受控）；设置人物隐私级别；回收站（查看已删除、单条/批量恢复，恢复时校验额度）
* 拦截规则（分场景）：额度用尽时隐藏新增、导入按钮，保留编辑、查看；订阅过期时隐藏全部操作按钮，仅保留浏览查看；两种场景均禁止批量导出

**Tab 2：亲属关系**
* 核心能力：解决传统家谱复杂关系，支持多父、兼祧、出继、嗣子、赘婿
* 功能入口：在人物详情中直接操作绑定关系；也可在此 Tab 全局查看和管理
* 功能：为指定人物绑定关系（生父/嗣父/兼祧父/继父/义父/母亲/配偶/赘婿/出继）；自动生成常规双向关系，特殊关系人工确认留存备注；查看某人全部亲属关系清单、关系备注溯源、修改记录

**Tab 3：世系图**
* 功能：整合垂丝图、宝塔图，自动渲染全族谱世系结构，支持缩放、拖拽、定点查看详情
* 续修适配：可切换查看历史定稿版本世系、当前续修编辑中世系，直观对比迭代差异
* 脱敏规则：已故人物全字段公开；在世人物按访问角色分级脱敏（公开访客/族内成员/拥有者主编）
* 交互：点击人物节点弹出人物详情卡，支持快速跳转至人物编辑

**Tab 4：字辈设置**

**四大传统版式详细规格**

**版式一：苏式垂丝图**
* 起源与特点：北宋苏洵所创，世代为经、父子垂直线为纬，形如垂挂丝线，是传统家谱最常见的世系图样式
* 布局结构：从上至下按世代排列，同代人物按长幼从左到右排列；父子间以竖直线（"丝"）连接；配偶并列于夫侧用横线连接
* 排版规则：世代间距24pt；人物间距最小20pt；信息框标准80pt×36pt；垂直线0.5pt深灰；分页在整代之间，不得拆分一代人；跨页标注"接前页第X代"
* 特殊情况处理：无子（无线标注"无传"）；多子（垂丝分岔连接各子）；兼祧（双垂丝+标注）；出继/嗣子（虚实线区分+标注）；多妻（正妻居右依次向左，妾用虚线）；女性（细边框/不同底色区分，出嫁女垂丝止于本身）

**版式二：欧式分栏**
* 起源与特点：北宋欧阳修所创，表格形式，世代分行人物分栏，由右向左递进（古法尚右），便于查阅上下代关系
* 布局结构：从右至左按世代排列，每栏一代；同一世代人物从上到下按长幼排列；上下代间用横线连接
* 排版规则：栏宽120pt可微调；行高40pt；连接线0.5pt；每栏顶部标注世代数；横向分页标注"前接第X世"；纵向分页标注"接前页第X世第X人起"
* 特殊情况处理：无子（空格标注"无传"）；多子（父格底部分多条横线）；兼祧（同一人物格+角标"兼祧"）；出继（本生父旁标注+嗣父格中列入）；配偶（夫格内记述，不单列格）

**版式三：宝塔式**
* 起源与特点：始祖为塔顶，子孙逐层展开，形如宝塔，直观展示家族树状结构，适合中小家族（200人以内）整体一览
* 布局结构：顶部居中为始祖；第二代左右对称展开；逐级加宽形成下宽上窄的宝塔形；父子间用斜向/纵向连接线
* 排版规则：节点直径40-50pt（圆形/圆角矩形）；层级间距60pt；同级间距最小30pt；连接线0.75pt；居中对称分布；字体始祖16pt逐层递减至最小10pt
* 特殊情况处理：无子（无分支线）；多子（长幼从左到右对称排列，奇数时正中对父）；兼祧（双线连两父+标注）；出继（虚实线+标注）；配偶（并列夫右侧，横线连接，尺寸略小/异色）；女性（不同形状/边框色区分）

**版式四：牒记式**
* 起源与特点：以人物传记为主体，按世代长幼逐条排列，每人一篇小传（"牒"），世系关系通过文字说明体现，是内容最详实的谱书格式
* 布局结构：按世代顺序排列；每世内按长幼排列；每人一条目，含标题（姓名+字号）和正文（传记）；世系关系在条目中用文字说明
* 排版规则：条目标题姓名三号黑体+字号小四宋体；条目间距空1行，首行缩进2字符；正文五号宋体1.5倍行距；每世前有"第X世"大标题；尽量避免条目中间分页；谱书前有人名目录按世代索引
* 特殊情况处理：无子（标注"无嗣"或"女一，适某"）；多子（按长幼列出"生子五：长某、次某…"）；兼祧（本生条目标注"出继与某公为嗣，兼祧本生"）；出继/嗣子（出继方与嗣父方条目各标注说明）；信息不详（标注"生卒未详""葬地失考"等，保留条目位置）

#### 前台页面 10：家族文化

**页面定位**：家族文化内容的统一管理入口，横切于六步流程（任何阶段都可录入和查看）。家族文化是族谱区别于普通人物名录的核心价值——它承载的是家族的精神传承、历史脉络和文化记忆，而非单纯的世系数据。

> **MVP 范围说明**：MVP 仅上**家规家训**和**家族大事记**两个 Tab（核心文化内容，结构化程度高、实现成本低）。**姓氏源流、堂号起源、家族相册**三个 Tab 放在 V1.5 上线，MVP 中隐藏入口并标注"V1.5 开放"。

**页面结构**：顶部 Tab 栏切换五个子模块（MVP 仅显示前两个）

**Tab 1：姓氏源流**
* 布局：富文本编辑器 + 结构化字段区
* 功能：记录本家族姓氏的起源、得姓始祖、历代迁徙路线、郡望堂号沿革
* 结构化字段：姓氏、得姓始祖、发源地、郡望、历代迁徙路线（时间 + 地点 + 原因，支持多条）
* 富文本区：详细叙述姓氏起源故事、历史名人、姓氏考辨
* 续修继承：续修时默认继承上一版内容，支持增量补充新考据

**Tab 2：堂号起源**
* 布局：堂号信息卡 + 富文本编辑器
* 功能：记录本族堂号的名称、来历典故、所属郡望、与同姓其他堂号的关系
* 结构化字段：堂号名称、别称、来历类型（地名/典故/先祖事迹/皇帝赐封）、关联郡望
* 富文本区：详细叙述堂号起源故事、堂联、堂号文化内涵
* 说明：堂号在族谱创建时已填写基础信息（族谱实体 tanghao 字段），此处补充完整起源叙述

**Tab 3：家规家训**

* 功能：以结构化条目形式管理家规家训，支持分类（祖训/家规/家训/族规/戒律）、排序、富文本内容
* 条目字段：标题、分类、内容（富文本）、出处（某代祖某公立）、排序号
* 说明：家规家训是家族精神传承的核心载体，不同于普通章节，需要结构化管理以便在排版定稿时按分类和顺序自动生成家训篇章
* 续修继承：续修时可继承历史家规，也可增补新订家训

**Tab 4：家族大事记**
* 布局：时间轴视图 + 列表视图双模式切换 + 新增/编辑事件弹窗
* 功能：以时间轴形式记录家族重大事件，支持按年代、事件类型筛选浏览
* 事件字段：事件日期（支持农历/公历文本）、事件类型（修谱/祭祀/迁徙/婚嫁/丧葬/科考/封赠/灾荒/建祠/其他）、事件标题、事件描述（富文本）、关联人物（可关联族谱中的人物）、关联附件（图片等）
* 时间轴视图：按年代从古至今排列，支持缩放、点击展开详情
* 列表视图：表格形式，支持筛选、排序、导出
* 续修继承：续修时自动继承历史大事记，可在时间轴末尾继续增补新事件

**Tab 5：家族相册**
* 布局：相册网格视图（瀑布流） + 按分类筛选 + 上传/管理弹窗
* 功能：家族公共相册，区别于人物个体照片——记录家族集体活动、祠堂祖宅、族谱老照片、家族聚会等

* 隐私控制：支持设置照片的可见范围（公开/族内可见/私密）

**横切规则**：

## 第四部分：全局兜底规范

### 4.1 全场景数据安全规则

* 数据安全原则：平台不主动删除用户业务数据，因运营原因（过期、欠费、冻结等）仅做功能权限拦截；用户主动删除遵循"回收站+软删除"二级机制，删除操作全程留痕。
* 分级隐私脱敏：公开访客、族内成员、主编、拥有者四级脱敏权限严格区分，在世人物隐私信息严格保护，已故人物史料完全公开，平衡隐私保护与族谱传承需求。
* 租户强隔离：所有业务数据、额度数据、权限数据严格按租户隔离，杜绝跨用户数据泄露、数据篡改、数据覆盖问题。

### 4.2 商业化闭环规则

* 所有高阶能力（排版定稿、版式锁定、成册PDF导出、新建续修、批量导入导出）全部与订阅状态、额度状态强绑定。
* 协作权限、额度消耗、功能拦截逻辑完全统一，所有子成员操作均归属租户主账号。
* 过期、欠费、冻结状态下仅保留只读阅览权限，所有写入、迭代、高阶功能全部拦截，构成SaaS年费商业模式闭环。

### 4.3 续修迭代闭环规则

* 单族谱唯一存续，多期续修无限迭代，历史版本封存只读，新版增量编辑，不篡改正统史料。
* 版本继承、版本隔离、版本对比、版本归档全流程打通，适配家族代代修谱、永续传承的核心需求。
* 流程可合规回退、可终审容错、可版本溯源，兼顾传统修谱严谨性与线上产品灵活性。

### 4.4 交互体验兜底规则

* 全站空状态、加载状态、报错状态、二次确认、防抖防重、并发锁、文件容错全覆盖。
* 权限与界面强一致，无权限功能自动隐藏，无置灰无效按钮，界面简洁统一、逻辑清晰。
* 多人协作无冲突、编辑独占锁、超时释锁、状态实时提示，适配家族多人协同修谱场景。

## 第五部分：非功能性需求

### 5.1 性能要求

| 指标 | 要求 | 说明 |
|------|------|------|
| 单族谱人物上限 | 10,000人 | 超过时提示"人物过多，建议分卷" |
| 世系图渲染 | ≤3,000人 不卡顿 | 超过3,000人时自动降级为"折叠+分代渲染" |
| PDF生成时间 | ≤500人/30秒，≤2000人/2分钟 | 详见 1.11.4 节 |
| 并发编辑 | 同一族谱同时在线编辑 ≤20人 | 协作锁机制保证数据不冲突 |
| 页面加载 | 首屏加载 ≤2秒（CDN加速） | 首页、工作台、族谱总览 |
| 接口响应 | 列表查询 ≤500ms，详情查询 ≤300ms | 不含PDF生成等异步任务 |
| 批量导入 | 单次 ≤1,000行 | 超出提示分批 |

### 5.2 存储规划

| 项目 | 规划 | 说明 |
|------|------|------|
| 单附件大小上限 | 20MB（图片）/ 50MB（PDF/扫描件） | 超出时拦截并提示 |
| 单族谱存储上限 | 由套餐额度控制（试用100MB / 基础2GB / 专业10GB） | 超额拦截上传 |
| 文件存储架构 | 对象存储（OSS/S3兼容） | 按租户ID分目录，避免跨租户访问 |
| 缩略图 | 图片上传后自动生成 200×200 缩略图 | 用于列表预览 |
| 备份策略 | 每日全量备份 + 实时增量备份 | 备份保留30天，支持按时间点恢复 |

### 5.3 安全要求

| 项目 | 要求 | 说明 |
|------|------|------|
| 数据传输加密 | 全站 HTTPS + TLS 1.2+ | 禁止HTTP降级 |
| 密码存储 | bcrypt 哈希，cost=12 | 不存储明文密码 |
| 密码强度 | 最少8位，需含字母+数字 | 注册/修改密码时校验 |
| 接口鉴权 | JWT Token，有效期2小时，支持滑动续期 | 所有业务接口需携带Token |
| 防注入 | 参数化查询，禁止SQL拼接 | 后端ORM统一处理 |
| 防XSS | 富文本内容入库前过滤危险标签 | 白名单机制（允许<p><br><strong>等，禁<script><iframe>等） |
| 防CSRF | 敏感操作（删除/支付/归档）需CSRF Token | 前端框架自动处理 |
| 速率限制 | 登录接口 5次/分钟，API接口 100次/分钟 | 防暴力破解和接口滥用 |
| 审计日志 | 所有关键操作永久留存，不可篡改 | 详见 OperationLog 实体 |

### 5.4 兼容性

| 项目 | 要求 |
|------|------|
| 浏览器最低版本 | Chrome 90+、Firefox 88+、Safari 14+、Edge 90+ |
| 分辨率适配 | 最低 1280×720，推荐 1920×1080 |
| 移动端适配 | 响应式断点 768px（平板）、375px（手机），MVP仅支持浏览，不支持编辑 |
| 操作系统 | Windows 10+、macOS 10.15+（Web端） |

### 5.5 可用性与运维

| 项目 | 要求 | 说明 |
|------|------|------|
| SLA目标 | 99.9% 月度可用性 | 年停机 ≤8.76小时 |
| 监控告警 | 接口错误率 >1% 告警、响应时间 >2秒告警 | 自动推送至运维群 |
| 灾难恢复 | RPO ≤1小时，RTO ≤4小时 | 每日全量备份 + 增量备份 |
| 数据擦除 | 用户主动申请数据擦除时，7个工作日内完成 | 需身份验证 + 二次确认 + 审计日志记录 |

### 5.6 合规性

| 项目 | 要求 | 说明 |
|------|------|------|
| 个人信息保护 | 遵循《个人信息保护法》（PIPL） | 收集个人信息需明示告知，最小化收集 |

| 隐私政策 | 注册时强制阅读并同意《隐私政策》和《用户协议》 | 版本更新时重新弹窗确认 |
| 内容合规 | 敏感词过滤 + 人工审核机制 | 详见后台"内容审核"模块 |
