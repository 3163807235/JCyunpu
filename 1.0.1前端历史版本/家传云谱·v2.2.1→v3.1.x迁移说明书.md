# 家传云谱 · v2.2.1 → v3.1.x 迁移说明书

**生效日期**：2026-09-15  
**目标基线**：[家传云谱·数字管理平台产品设计文档_v3.1.md](./家传云谱·数字管理平台产品设计文档_v3.1.md) **v3.1.6（开发基线·冻结）**  
**源基线**：[家传云谱·产品设计文档.md](./家传云谱·产品设计文档.md) v2.2.1（已废止）

## 1. 迁移目标与原则

### 1.1 目标

| 维度 | v2.2.1（旧） | v3.1.6（新） |
|------|-------------|-------------|
| 流程 | 六步：启动→**采集**→编排→质量审核→排版→归档（`current_stage` 1–6） | 五步：启动→编排→**校对**→智能排版→归档（`current_stage` 1–5） |
| IA | 侧栏围绕修谱阶段；采集为阶段菜单 | **双区**：日常管理区始终可见 + 修谱流程区按进度展开 + 横切资料档案 |
| 人丁 | 采集阶段录入；语义上偏项目隔离 | **信息管理**常态录入；Person/Relationship 为**族谱级活数据** |
| 进度条 | 五步成谱含「广录族人」段；简易仍 5 段 | 段数=内部步数；广录族人=工作台**行动卡**；简易 **4 段** + `barIndex` 映射 |
| 审核 | 质量审核 | 校对（文案与菜单） |

### 1.2 原则

1. **先架构迁移（Sprint M），再继续业务 Sprint**——禁止在六步模型上叠加双区半成品。  
2. **Mock / 类型 / 路由 / store 同批对齐**，避免页面已五步、类型仍六步。  
3. **后端未就绪时**：前端 Mock 按新模型实现；接口字段预留与 v3.1.6 §1.7 一致。  
4. **续修 / RenewalItem / OCR Spike**：按文档范围，入口隐藏或 Spike，不阻塞首修闭环。

## 2. 阶段编号映射

### 2.1 内部阶段（current_stage）

| 旧 stage | 旧名称 | 新 stage | 新名称 | 说明 |
|----------|--------|----------|--------|------|
| 1 | 项目启动 | **1** | 项目启动 | 不变 |
| 2 | 数据采集 | — | （取消阶段） | 能力迁入日常区「信息管理」 |
| 3 | 内容编排 | **2** | 内容编排 | |
| 4 | 质量审核 | **3** | 校对 | |
| 5 | 排版定稿 | **4** | 智能排版 | |
| 6 | 发布归档 | **5** | 发布归档 | |

**数据迁移公式（持久化 / Mock）**：

```
if old_stage == 1: new = 1
elif old_stage == 2: new = 1   # 采集中视为仍停在启动后、编排前；也可定 new=2，见下「策略」
elif old_stage == 3: new = 2
elif old_stage == 4: new = 3
elif old_stage == 5: new = 4
elif old_stage == 6: new = 5
```

**采集中（old=2）策略（推荐）**：映射为 `new=1`，工作台「广录族人」行动卡高亮，引导去信息管理；避免用户一进编排却仍 0 人。若产品希望「已在采集即视为可编排」，可改为 `new=2`，须在发布说明中写清。

### 2.2 简易模式跳步

| 场景 | 旧 | 新 |
|------|----|----|
| 跳过审核 | 3→5（跳过 4） | **2→4**（跳过 3 校对） |
| 回退 | 5→3 | **4→2** |
| 推进到排版时 | — | 批量 `review_status=1`（v3.1.6） |

### 2.3 进度条 barIndex（禁止 `barIndex = current_stage`）

标准模式（5 段）：`barIndex = current_stage`（1–5 一一对应）。

简易模式（4 段）：

| current_stage | barIndex |
|---------------|----------|
| 1 | 1 |
| 2 | 2 |
| 4 | **3** |
| 5 | **4** |

段名：标准「壹·立堂定源 → 贰·协同编纂 → 叁·三校勘误 → 肆·付梓定稿 → 伍·颁谱典藏」；简易「启动 → 编排 → 定稿 → 归档」。**不再使用「贰·广录族人」作为进度段。**

## 4. 数据模型迁移

### 4.1 Person / Relationship

| 项 | 旧语义 | 新语义（v3.1.6） |
|----|--------|------------------|
| 归属 | 偏项目（文档）/ 前端已有 `genealogyId` | **权威：`genealogy_id`**；`project_id` 可空，仅追溯 |
| 审核 | `review_status` | 保留；重置触发：`current_stage ∈ {3,4}` |
| 归档后变更 | 无或不完整 | `is_changed_since_archive`：0/1/2/**3=删除** |
| 关系 | 宜挂族谱 | 与 Person 同，挂 `genealogy_id` |

前端现状：`Person.Item` 已有 `genealogyId`，迁移成本低于文档旧版「人物挂项目」。后端若仍按 `project_id` 必填，须出库脚本改为可空并回填 `genealogy_id`。

### 4.2 Project

新增字段（Mock/类型先落地）：

- `layout_dirty`: 0 \| 1  
- `current_stage`: 1–5（替换 1–6）

### 4.3 RenewalItem（V1.5 功能，模型可预留）

见 v3.1.6 §1.7.19。MVP：类型与 Mock 可空实现，**UI 入口隐藏**。  
**首修排版**：`project_type=1` → 全量 `is_deleted=0` 人物，不经 RenewalItem。

### 4.4 VersionSnapshot

归档时序列化：族谱级 Person+Relationship + 项目级 Chapter + 文化 + 附件清单。续修**不恢复**人物表，仅对比增补清单。

## 5. 业务规则迁移（实现检查表）

| 规则 | 实现要点 | MVP |
|------|----------|-----|
| 创建族谱 | 自动建初始修谱项目 stage=1 | 是 |
| 广录族人 | 工作台行动卡 → `/info`，非进度段 | 是 |
| 编排→校对 | 人物数=0 禁用推进 | 是 |
| 校对/排版改人 | 重置 review_status；排版置 layout_dirty | 是 |
| 标准模式脏数据 | 须回校对终审后方可导出 | 是 |
| 简易模式脏数据 | 排版页「确认纳入」批量置 review_status=1 | 是 |
| 简易推进排版 | 首次进入排版批量 review_status=1 | 是 |
| 归档后 | 只锁项目级；日常区仍可写活数据 | 是 |
| 续修 / RenewalItem | 入口隐藏 | 否（V1.5） |
| OCR | Spike，非硬交付 | Spike |
| 分支负责人 / 校对邀请 | 隐藏 | V1.5 |

## 6. Sprint M 建议排期（迁移专用）

> 建议单独开 **Sprint M**，完成前不开启依赖五步语义的新业务页。

| 序号 | 任务 | 验收 |
|------|------|------|
| M1 | 类型与 Mock：`Stage` 1–5、stage 迁移脚本、layoutDirty | Mock 族谱列表 stage∈[1,5] |
| M2 | `stage.ts` + 进度条组件 + barIndex | 标准 5 段 / 简易 4 段展示正确 |
| M3 | 路由菜单双区 + `info` + collect 重定向 | 侧栏分区正确；旧 collect URL 可进信息管理 |
| M4 | collect UI → info；overview 行动卡 | 0 人高亮行动卡；录入不依赖 stage |
| M5 | 推进/回退/门禁按五步；校对/排版文案 | 简易跳过校对；0 人不可进校对 |
| M6 | layout_dirty + 双模式确认路径 | 改人后禁导出；简易一键确认可导出 |
| M7 | 文案与 i18n、文档交叉引用清理 | 无「质量审核」「数据采集阶段」用户可见文案 |
| M8 | 更新本仓库 MVP 计划状态；冒烟五步首修 | 建谱→录人→编排→校对/跳过→排版→归档 Mock 跑通 |

**预估**：前端 Mock 路径约 3–5 人日（视回归范围）；有后端时另加契约与数据脚本。

## 7. 风险与回滚

| 风险 | 缓解 |
|------|------|
| 用户书签 `/collect` | 保留重定向 ≥1 个迭代 |
| 本地 session 中旧 stage=6 | 进入族谱时运行映射函数写回 |
| 半迁移导致门禁错乱 | M1–M3 合并合入；禁止只改菜单不改 Stage 类型 |
| 与旧文档并行开发 | Cursor 规则与废止声明已切换；PR 描述须引用 v3.1.6 |

**回滚**：仅紧急情况回退到 v2.2.1 标签/提交；回滚后须恢复文档状态声明。默认**不回滚产品基线**。
