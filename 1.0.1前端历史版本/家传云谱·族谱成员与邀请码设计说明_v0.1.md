## 1. 背景与问题

当前 v3.1.6 将「能进某本族谱的登录用户」主要落在 **Collaborator（协作成员）** 上，并另有：

- **项目启动 · 团队配置**：本期修谱理事会名录（`Project.editors` 等），临时、项目级；
- **族内只读分享链接**：可不登录，临时只读，**不算**正式归属；
- **V2.0「族人注册浏览」**：完整传播增长能力尚未拆成可开发的最小实体。

业务诉求：**普通族人凭邀请码注册或登录后加入已建族谱**，身份是「族谱成员」，**不是**协作采编，也**不是**本期修谱理事会席位。

---

## 2. 三层身份（强制区分）

| 层级 | 名称 | 英文/标识 | 数据载体 | 是否占协作席位 | 默认能力 |
|------|------|-----------|----------|----------------|----------|
| L1 | **族谱成员** | `GenealogyMember` / `member` | 新实体（见 §4） | **否** | 登录后进入该族谱，**只读浏览**（见 §5） |
| L2 | **协作人员** | `Collaborator` | 既有 §1.7.16 | **是**（计入 `max_collaborators`） | 按角色编辑/流程（MVP：拥有者+采编） |
| L3 | **本期修谱成员** | 理事会名录 | `Project.editors` 等 | 否（名录快照） | 仅本期组编展示；保存可**单向邀请**为 L2 采编 |

### 2.1 互斥与升级

* 同一用户在同一族谱：**至多一条** `GenealogyMember`；若同时是 `Collaborator`，以协作角色权限为准（成员记录可保留作归属标记，或合并展示「成员+采编」）。
* **成员 → 协作**：须拥有者在「权限管理 · 角色管理」另行邀请采编（或 V1.5+ 其它协作角色），走 Collaborator 流程，占席位、耗额度规则不变。
* **协作 → 成员**：移除协作后，可选保留成员身份（只读）或一并移除；默认 **保留成员**（避免误踢出族）。
* **本期组编移除**：只改 `Project.editors`，**不**移除成员、**不**撤协作（与既有「只加邀不撤权」一致）。

### 2.2 与分享链接的边界

| | 族谱成员 | 族内分享链接 |
|--|----------|--------------|
| 是否需登录账号 | 是 | 否（或轻量） |
| 是否写入归属关系 | 是（GenealogyMember） | 否 |
| 是否出现在「我的族谱」 | 是（只读标签） | 否 |
| 撤销方式 | 拥有者移除成员 / 成员退出 | 撤销链接 |

## 3. 范围与版本

### 3.1 本草案纳入（MVP 增补候选）

| 编号 | 能力 | 说明 |
|------|------|------|
| M-P0 | 族谱邀请码 | 每本族谱一个可刷新的成员邀请码（见 §6） |
| M-P0 | 注册填邀请码 | 注册表单必填或按策略选填（见 §7.1，默认 **选填**；有码则注册成功后自动加入） |
| M-P0 | 登录后加入 | 「我的族谱」「个人中心」提供「输入邀请码加入族谱」 |
| M-P0 | 成员只读进谱 | 加入后可进入工作台等只读视图，无写权限 |
| M-P1 | 拥有者管理成员 | 权限设置或独立「族谱成员」列表：查看/移除/重置邀请码 |

### 3.2 明确不做（本草案）

* 邀请码直接授予采编/主编等协作角色（必须走角色管理）。
* 邀请码写入本期团队配置名录。
* 开放无码「搜索族谱申请加入」（V2+）。
* 成员侧编辑人丁、推进流程、管理协作、购买消耗拥有者额度的写操作。

### 3.3 与原路线图关系

* 从 **V2.0「族人注册浏览」** 拆出 **最小可交付切片**（邀请码 + 成员只读），提前到 v3.1.7 候选。
* 原 Collaborator.`viewer`（V1.5）：**协作体系内的只读角色**；本草案的 **member** 为 **归属体系**。长期可并存：member 解决「是不是本族人」；viewer 若仍需要，仅用于「协作席位内的只读岗」。推荐新产品文案统一称「族谱成员」，避免与「只读浏览协作角色」混称。

## 4. 数据模型

### 4.1 实体：族谱成员（GenealogyMember）

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | bigint | 是 | 主键 |
| genealogy_id | bigint | 是 | 所属族谱 |
| user_id | bigint | 是 | 成员用户 ID（其自身 tenant_id 不变） |
| display_name | varchar(64) | 否 | 展示名；空则用用户昵称 |
| status | tinyint | 是 | 1=正常，2=已退出，3=被移除 |
| join_source | varchar(32) | 是 | register_invite=注册时带码，manual_code=登录后填码，owner_add=拥有者后台添加（预留） |
| invite_code_used | varchar(32) | 否 | 加入时使用的邀请码（审计） |
| joined_at | datetime | 是 | 加入时间 |
| left_at | datetime | 否 | 退出/移除时间 |
| created_at / updated_at | datetime | 是 | |

**约束**：`UNIQUE(genealogy_id, user_id)`（含历史可用 status 软过滤，或移除后允许再次加入）。  
**索引**：`(user_id, status)`、`(genealogy_id, status)`。

### 4.2 实体：族谱邀请码（GenealogyInviteCode）

挂在族谱上，**面向成员**，与 `Collaborator.invite_token`（面向协作定向邀请）分离。

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | bigint | 是 | 主键 |
| genealogy_id | bigint | 是 | 所属族谱；一谱可保留历史码，**当前有效码唯一** |
| code | varchar(16) | 是 | 邀请码；大小写不敏感；建议 8 位字母数字，排除易混字符 |
| status | tinyint | 是 | 1=有效，0=已作废 |
| max_uses | int | 否 | 最大使用次数；空=不限制（MVP 可先不限制或默认 200） |
| used_count | int | 是 | 已成功加入次数 |
| expire_at | datetime | 否 | 过期时间；空=不过期（MVP 默认不过期，拥有者可设 30/90 天） |
| created_by | bigint | 是 | 生成人（拥有者） |
| created_at / revoked_at | datetime | 是/否 | |

**建谱时**：系统自动生成一条有效邀请码。  
**重置**：作废旧码并生成新码；已加入成员不受影响。

### 4.3 ER 关系（相对 v3.1.6 增补）

```
族谱（Genealogy）
  ├──1:N── 协作成员（Collaborator）      ← L2 编辑/流程权限
  ├──1:N── 族谱成员（GenealogyMember）    ← L1 归属只读（本草案）
  ├──1:N── 族谱邀请码（GenealogyInviteCode）
  └──1:N── 修谱项目（Project）
            └── 本期组编名录 editors…   ← L3 临时名录
```

### 4.4 隐私模式补充

在 §1.8 隐私规则上增加：

* `privacy_mode = 1`（完全私有）：拥有者、**协作成员**、**族谱成员**可登录访问；非成员不可见。
* 族谱成员查看在世人物：按 `living_desensitize` 脱敏（与协作只读一致，**不可**见拥有者「完整显示」特权）。

## 5. 权限（族谱成员）

成员 **可以**：

* 在「我的族谱」看到该族谱卡片，角标「成员 · 只读」；
* 进入族谱工作台、信息管理（只读列表/图谱）、家族文化（只读）、资料档案（仅预览已有，不可上传）、修谱流程区已到达阶段的 **只读预览**；
* 退出该族谱（二次确认）。

成员 **不可以**：

* 新增/编辑/删除人物与关系、上传附件、改章节、推进/回退流程、排版定稿、归档；
* 邀请协作、管理成员（非拥有者）、改隐私/基础设置、查看额度与订单；
* 出现在「角色管理」协作席位占用数中。

拥有者订阅过期时：成员与协作一律 **全只读**（与现规则一致）。

## 6. 邀请码规则

1. **用途**：仅用于加入 **族谱成员（L1）**，文案禁止写「协作邀请码」「采编码」。
2. **展示**：拥有者可在 **我的族谱 · 自建卡片「邀请码」**、以及「权限设置 · 族谱成员」查看/复制/重置；创建成功 toast 可提示「已生成成员邀请码」。
3. **校验失败**：码不存在、已作废、已过期、次数用尽、用户已是该谱成员/拥有者 → 明确错误文案。
4. **注册带码**：校验通过则 `register_source` 可记 `invite`；注册成功事务内写入 GenealogyMember。
5. **安全**：码不可枚举（足够熵）；接口限流（如 10 次/分钟/IP）；操作写入 OperationLog（`log_category=collab` 或新增 `member`）。

## 7. 交互说明

### 7.1 注册页

* 表单在密码确认与协议之间增加：**「族谱邀请码」**。
* **MVP 策略（默认）**：**选填**。占位符：「若受邀加入已有族谱，请填写邀请码」。
* 勾选说明短文案：「填写后注册成功即成为该族谱成员（只读）；成为采编需族谱拥有者另行邀请。」
* 若填写：提交前本地格式校验（长度/字符集）→ 注册接口携带 `inviteCode` → 失败则整单失败并提示（避免注册成功但未入谱的困惑）。**备选策略**：注册成功但入谱失败时跳转登录并带 `?join=` 重试——不推荐作默认。
* 支持 URL：`/auth/register?code=XXXXXXXX` 自动填入。

### 7.2 我的族谱（页面 02 增补）

* 顶部操作区增加次要按钮：**「邀请码加入」**（与「创建族谱」并列；创建仍受套餐「自建族谱数」限制，**加入成员谱不占自建名额**）。
* 弹窗：输入邀请码 → 预览族谱名称/堂号（脱敏接口）→ 确认加入 → 列表刷新，卡片标注「成员 · 只读」。
* **自建谱卡片**增加 **「邀请码」** 按钮：弹窗展示当前成员邀请码，支持复制 / 重置（与权限设置 · 族谱成员同源）；成员谱卡片不展示此按钮。
* **族谱编号可见**：卡片展示对外编号 `genealogyNo`（如 `JP-001001`），与内部主键 `id`、成员邀请码分离；旧数据可由 id 回填。供客服报号 / 多租户运维，**不是**邀请码。
* 成员卡片操作：仅「进入」；无「编辑」「删除」「邀请码」（删除/发码仅拥有者自建谱）。
* 空态：除「立即创建」外增加「有邀请码？加入族谱」。

### 7.3 个人中心（页面 14 增补）

* 「账号信息」Tab 下方或独立入口卡片：**「加入族谱」**——同 7.2 弹窗（可复用组件）。
* 可选展示：「我加入的族谱」只读列表（名称 + 进入链接），与「我的族谱」数据同源过滤 `join_role=member`。

### 7.4 拥有者侧（页面 12 · 权限设置 增补，P1）

* 区块「族谱成员邀请」：当前邀请码、复制、重置、可选有效期/次数。
* 区块「成员名单」：手机号/昵称、加入时间、来源、移除。
* **不得**与「角色管理 · 邀请采编」混在同一按钮。

### 7.5 文案对照（防混淆）

| 场景 | 正确文案 | 禁止文案 |
|------|----------|----------|
| 注册/加入 | 族谱邀请码、加入族谱、成员（只读） | 协作码、采编码、修谱席位 |
| 角色管理 | 邀请采编、协作席位 | 邀请成员（易混） |
| 团队配置 | 本期理事会、保存本期组编 | 邀请码加入 |

## 8. 接口草案（供 OpenAPI / Mock）

| 方法 | 路径（示例） | 说明 |
|------|----------------|------|
| GET | `/api/genealogy/invite-codes/preview?code=` | 未登录也可：返回族谱显示名等预览 |
| POST | `/api/auth/register` | Body 增加可选 `inviteCode` |
| POST | `/api/genealogy/members/join` | 登录后：`{ code }` → 加入成员 |
| GET | `/api/genealogy/list` | 增加字段 `membership`：`owner` \| `collaborator` \| `member` |
| GET | `/api/genealogy/{id}/invite-code` | 拥有者：当前有效码 |
| POST | `/api/genealogy/{id}/invite-code/rotate` | 拥有者：重置 |
| GET | `/api/genealogy/{id}/members` | 拥有者：成员列表 |
| DELETE | `/api/genealogy/{id}/members/{userId}` | 拥有者：移除 |
| POST | `/api/genealogy/{id}/members/leave` | 成员：自行退出 |

统一响应仍为 `{ code, msg, data }`。
